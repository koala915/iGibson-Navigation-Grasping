# 退出與續巡的第二輪複查（2026-10-21）

範圍：投放／未夾到後的退出、巡航拒絕後補退、重啟辨識許可，以及轉向放置盒前的
後退距離預算。本次修改 PC 程式，沒有連車送動作、沒有啟動／打斷任務、沒有更新車上服務。

## 找到並修正

| 問題 | 可能表現 | 修改 |
|---|---|---|
| 巡航結束會 maintenance-lock，但總控補退前沒有解鎖 | 有空間卻不動，等到里程逾時 | `prepare_back_out` 先確認停止、空手、travel、手臂不忙、無其他底盤 client；必要時要求解鎖並讀狀態確認後才退 |
| 補退沿用補退前累積的 clear 計數 | 原本要求五張無目標畫面，重試時一張就出發 | 重置 clear 與停止參考時間，重新累積新畫面 |
| 巡航清理失敗仍可能被當成可重試拒絕 | maintenance-lock timeout 等故障後又重試或補退 | `cleanup_error` 一律停止；兩種可恢復分類也明確排除清理故障；未提供脈衝數不當作確定零動作 |
| 讀不到實際後退距離時，原本以要求距離扣帳 | 未動／動了多少不明，仍把距離記成完成 | `back_straight` 拒絕 None、零、負數、NaN、Inf、bool；總控硬體路徑也拒絕未知距離 |
| 朝放置盒轉向前的後退仍用要求值累計 | 滑行未計入上限，可能額外多退幾步 | 兩個真實後退包裝器回傳里程，`face_box` 用實際行進量扣帳，超限停止；保留原地轉向許可閘 |
| 巡航拒絕後的 `Room.make` 沒有與 `leave` 共用退出複查 | 固定補退 10cm 後，仍可能停在外圈不合法處 | 補退前按剩餘預算重新找含轉彎外圈的出口；補退後共用定位複查／有限修正，受總 0.60m 與額外 0.20m 兩個預算限制 |

涉及生產檔案：`integration/mission_loop.py`、`integration/sugarbox_approach_grasp.py`。
放置盒包絡、牆面距離、35cm 遮罩、速度與低階逐段防撞維持。
恢復辨識原有五張要求，沒有新增固定 sleep。

## 仍可能停止的情況

1. 定位遺失／過期／跳動：不能靠猜測位置繼續後退或轉彎。
2. 完整車身的安全退路被牆或放置盒擋住，或在 0.60m 內沒有合法退出點。
3. 動態障礙、相機辨識無法確認、服務狀態或清理失敗。
4. 實際滑行超出預算：記錄超限並停止，不再追加後退。

這些狀況仍會保持停止；不會藉由放寬盒子保護或重複下動作來「恢復」。本次離線複查
能驗證已知案例與程式契約，不能保證實車永遠不停。下一次新啟動 PC 總控才讀入修正，
仍需旁站實車驗證，尤其是補退解鎖與補退後接回巡航。
