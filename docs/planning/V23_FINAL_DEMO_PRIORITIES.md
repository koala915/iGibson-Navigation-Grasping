# v23 決賽 demo 目的與優先順序

## 主要目的

在現場完成可重複的「開機檢查 → 巡航／接近 → 夾取 → 收臂搬運 → 投放 → 接續任務」。
導航與手臂共用唯一常駐 Serial 持有者，避免反覆載入 PPO／YOLO 與相互搶埠。
短暫雜訊、斷訊或個別脚本故障應先停等、有限修復，確認正常後接續；
無法恢復時降低展示功能並明確顯示原因，不能把未知動作盲目重播成成功。
所有階段須保留 RAM 餘裕，監督／日誌／影像不可無限累積。

目前可用程式入口為 v23 定點視覺夾取、原地投放與有限短直線計畫。
完整自主尋物、對準、垃圾桶導航及正式場地定位仍是目標，尚未完成驗收。
場地先以 2×1 m layout 驗證，擴充至 2×2 m 後再重驗地圖與定位。

## 部署與恢復界線

新版仍未取代實機正式服務。Jetson `/tmp` 的 Linux 測試使用 fake Serial／假控制器，
沒有實機動作，也不是現場功能驗收。
感測服務可有限重啟；Serial 故障升級需新版 API、足夠 RAM、idle／空夾爪／巡航位、
沒有未知 checkpoint，且取得原子 restart-lock。
監督器每次開機最多主動重啟 owner 一次；重啟使 PID 與 odom 原點改變，
舊任務不能自動續跑，导航必須重新驗證／定位。
UI 停止不是伺服機立即斷電。系統完全無回應或實際運動無法確認時保留診斷，
不以強制重啟與自動動作掩蓋故障。
